# Политика архива устаревших файлов

**Статус:** ЗАФИКСИРОВАНО 22.09.2026; дополнено 23.09.2026  
**Цель:** не удалять историю, но не путаться в рабочих папках.

## Куда

```text
archive/
  README.md          — оглавление архива
  docs/              — устаревшие документы (копии / переносы)
  public-assets/     — старые картинки/звуки, снятые с UI (S15+)
  code-snapshots/    — редко: снимок удалённого модуля
```

Корень `archive/` **в git**. Крупные бинарники — `archive/public-assets/_binaries/`
(в `.gitignore`).

## Когда архивировать

| Когда | Что |
|---|---|
| **Сейчас (до мегафайла)** | Устаревшие **документы** и таблицы (зоны, старые концепты), на которые больше не ссылаемся |
| **S15** | Бинарники, `_dev-placeholders/`, отвергнутые стоки, всё помеченное «не генерировать» в мегафайле |
| **После единого мегафайла** | Разрозненные черновики, полностью заменённые одним файлом |

## Агент

1. Переносит в `archive/...`, обновляет `archive/README.md`.
2. Из **активных** `docs/`, `AGENTS.md`, skills — **не ссылается** на архив как на SSOT
   (допустима одна фраза «история в archive/»).
3. Рабочие пути ассетов — только актуальный манифест / мегафайл.

## Чего не делать

- Не `git rm` без копии в `archive/`, если файл ещё может пригодиться как референс
- Не архивировать рабочие `src/games/*`
- Не читать архив «по умолчанию» при новых задачах

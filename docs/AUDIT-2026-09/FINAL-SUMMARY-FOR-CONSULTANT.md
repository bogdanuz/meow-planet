# Планета Мяу — итоговый отчёт аудита 24.09.2026 (для внешнего консультанта)

**Проект:** «Планета Мяу» — PWA-хаб из 9 обучающих мини-игр для детей 2–3 лет. iPad landscape, без backend, офлайн через Service Worker, все данные только в localStorage/IndexedDB.  
**Версия до аудита:** 0.15.22. **Версия после аудита:** **0.15.23**.  
**Стадия роадмапа:** не изменилась. Сейчас **S16** (генерация и подключение финальных картинок/звуков), дальше **S17** (публикация MVP). Этот аудит — ремонт существующего кода-каркаса, **не** замена S16/S17.

Полные материалы аудита — папка `docs/AUDIT-2026-09/`:
`00-CONTEXT.md`, `01-CODE-REVIEW.md`, `02-UX-UI-AUDIT.md`, `03-CONTENT-AUDIT.md`, `04-FINAL-FIX-PLAN.md`, `05-IMPLEMENTATION-LOG.md`, `06-TEST-REPORT.md`, `07-REPO-CLEANUP.md`. Этот файл — сводка всех восьми для человека, который не читает весь репозиторий.

## 1. Что делалось и в каком порядке

1. **Этап 0 (только чтение).** Сверка по `HANDOFF.md`, `AGENTS.md`, `docs/05-CURRENT-STATE.md`, `docs/06-ROADMAP.md`, `docs/07-SPRINTS.md`, `docs/08-KNOWN-ISSUES.md`, брифам всех 9 игр, правилам и skill-файлам проекта. Никаких изменений кода.
2. **Этап 1 (только чтение).** Построчный код-ревью `src/app`, всех 9 `src/games/<id>`, `src/shared`, `src/mascot`, `src/content`, `src/styles`, PWA-слоя, CI. Найдено 20 пунктов (таблица CR-01…CR-20).
3. **Этап 2 (только чтение).** UX/UI-аудит всех экранов относительно правил проекта (`toddler-interaction.mdc`, `ux-ui-kids-hub`) и внешних 2025–2026 практик для тач-интерфейсов малышей 2–4 лет.
4. **Этап 3 (только чтение).** Аудит всех текстов: детский слой, родительский слой, сверка брифов S14 с реальным кодом.
5. **Этап 4 (только документ).** Сведение всех находок в один план с приоритетами Критично/Средне/Некритично + открытые продуктовые вопросы. Показан владельцу через AskQuestion — **владелец подтвердил план целиком**.
6. **Этап 5 (реализация, TDD).** Правки кода по плану — см. раздел 3 ниже.
7. **Этап 6 (тесты).** Полный прогон unit + e2e до и после правок, регрессионные тесты на каждый исправленный баг.
8. **Этап 7 (гигиена репозитория).** Список файлов-кандидатов на архивацию (ничего не удалено без отдельного согласия).

### 2.5 Некритично / технический долг (зафиксировано, не исправлялось)

- CR-07, CR-08 — «Куда положить?» импортирует палитру цветов из «Лопни шарик», «Собери фигурку» импортирует геометрию слота из «Собери пазл». Формально нарушает правило проекта «игра не импортирует игру» — общий код надо вынести в `src/shared/`. Не сломано, но при правках одной игры может неожиданно задеть другую.
- CR-11 — часть коротких `setTimeout` (покачивание, праздник) не входит в набор, который снимается при выходе из игры; после ухода может доиграть доля секунды анимации/звука.
- CR-12 — при выходе из «Собери пазл» во время загрузки своего фото возможен редкий «хвост» асинхронной операции.
- CR-13 — в `src/shared/storage.ts` версия схемы настроек всегда пишется как текущая, миграции между версиями нет (сейчас не нужна — схема не менялась).
- CR-14 — функция удаления своего фото пазла существует, но никнуда не подключена — старые фото остаются в IndexedDB, пока их не сотрут вручную в данных браузера.
- CR-18 — балон-поп вставляет реплику маскота через `innerHTML`, но строка предварительно экранируется (`escapeHtml`); имя ребёнка туда не подмешивается напрямую. Работает безопасно, но правильнее собирать фразу через DOM-узлы без `innerHTML` вообще.
- CR-19 / K-005 — настоящего ESLint нет, `npm run lint` — это алиас на `tsc` (проверка типов). Причина — `typescript-eslint` пока не поддерживает TypeScript 7 (открытый issue в их репозитории). Решение отложено, не наше.
- CR-20 — если localStorage откажет (переполнена память браузера/приватный режим), настройки тихо не сохранятся без предупреждения родителю.

### 2.6 UX/UI-находки (детали — `02-UX-UI-AUDIT.md`)

- Часть тап-целей меньше внутреннего порога проекта 56px: вкладки и буквы в «Звуках» (~46px), кнопки режимов и навигации в «Лопни шарик» (44–48px). **Исправлено** — подняты до 56px.
- Задания в «Считаем с Мяу» и тосты в «Временах года» / «В гостях у Мяу» были длинными фразами, которые ребёнок 2–3 лет не может прочитать сам — вся смысловая нагрузка держалась на взрослом рядом. **Исправлено** — тексты укорочены (см. раздел 3).
- Маскот ведёт себя по-разному от игры к игре (где-то на сцене, где-то только в тосте) — это результат последовательных решений владельца в S14, не случайность. Зафиксировано как открытый вопрос на будущее (после арта S16).
- Книжный стиль пока не общий — часть экранов на CSS-фигурах и emoji (сезоны, счёт, дом). Это ожидаемый долг текущей стадии, закрывается в S16 картинками по MEGAFILE, не код-багом.

### 2.7 Текстовые находки (детали — `03-CONTENT-AUDIT.md`)

- Верхняя часть брифа «Собери фигурку» (`docs/games/S14-shape-build-BRIEF.md`) описывала старую версию экрана (скелет до 0.15.9) и противоречила актуальному коду. **Исправлено** — устаревший блок убран, оставлена ссылка на актуальный раздел решений.
- Шапка `docs/games/S14-GAMES-INDEX.md` показывала версию пакета 0.15.14, хотя реальный пакет уже был 0.15.22. **Исправлено**.
- Родительские описания игр («Развивает: …») местами были общими словами без опоры на механику («реакция», «внимание», «терпение» — по факту оценка ребёнка). **Исправлено** — переписаны на конкретное описание механики.
- Разговорные фразы соответствуют правилу «без наказания» везде — это подтверждено, не нарушено.

## 4. Тесты — до и после

| | До правок (первый прогон) | После правок |

| `npm run typecheck` | не прогонялся отдельно до этого аудита в этой сессии | **зелёный** |
| `npm run test` (Vitest, unit) | — | **151 из 151** зелёных (46 файлов); добавлено 3 новых теста на найденные баги |

| `npm run test:e2e -- --project=chromium` (Playwright) | **34 из 38** зелёных, 4 красных | **38 из 38** зелёных |

**Почему падали 4 e2e-теста** и как исправлено — подробно в `06-TEST-REPORT.md`. Короткая версия: три теста ссылались на старое название кнопки режима счёта («Дай Мяу» вместо актуального «Дай сколько») и на одну конкретную фразу похвалы вместо всего пула фраз — это устаревшие тесты, не баг приложения; один тест кликал по кнопке шаблона, которая была уже выбрана и перекрыта оболочкой — упрощён сценарий клика. Логика приложения в этих 4 случаях не менялась, только сами тесты приведены в соответствие с текущим кодом.

**Новые регрессионные тесты**, специально написанные под баги из этого аудита:
- `tests/unit/app-version.test.ts` — версия в коде всегда равна версии в `package.json`.
- `tests/unit/sound-world-unmount.test.ts` — закрытая игра не реагирует на поздний ответ сети.
- Добавленный кейс в `tests/unit/balloon-pop.test.ts` — повторный `evaluatePop` при нуле оставшихся целей не помечает задание завершённым второй раз.

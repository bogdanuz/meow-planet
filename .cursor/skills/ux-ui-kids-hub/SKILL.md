# UX/UI — хаб для малышей 2–3 лет

## Когда читать

Любой визуал / layout / кнопки / welcome / меню. Сначала этот skill, потом код.
Детали и антипаттерны: [reference.md](reference.md).

## Продуктовый контекст (не забывать)

- Ребёнок **не читает**. Текст — для взрослого или декоративный бренд.
- iPad, **только landscape**. Детские цели: **56–64 CSS px** (консервативный внутренний ориентир) + **большой зазор** между соседними целями; главный CTA (Play) может быть крупнее.
- Стиль: **книжная иллюстрация** (`docs/09-VISUAL-DESIGN-RESEARCH.md`).
- Нет очков, проигрыша, рекламы, модалок-меню поверх контента.
- Path A: скелет без финального арта — но скелет **не должен выглядеть как поломанный макет**.

## Жёсткие правила композиции

1. **Один фокус на экран.** Первый взгляд = одно главное действие или один герой.
2. **Нет «пустого центра».** Если середина экрана пустая — ошибка layout.
3. **Нет emoji/кругов «как будто персонаж»** там, где потом будет арт. Либо CSS-силуэт/форма с явной пометкой-заглушкой в коде, либо место под `<img>` с осмысленным aspect и размером.
4. **Не дублировать заголовок** (chrome + hero + подсказка с тем же смыслом).
5. **Главный CTA крупнее вторичных** в ≥1.5–2 раза и визуально «тяжелее» (цвет, тень, пульс).
6. **Вторичное (звук, родители) — в угол**, низкий контраст, не конкурирует с Play.
7. **Анимация с смыслом:** зовёт тапнуть / показывает жизнь. Не мигать всем фоном.
8. **Скролл только в выделенной области** (меню плиток), страница хаба зафиксирована.
9. Перед сдачей экрана — чеклист в [reference.md](reference.md) § Self-check.

## Welcome / первый экран

Цель: за 1 взгляд понятно «это Планета Мяу» и «сюда тапай, чтобы играть».

| Делать | Не делать |
|---|---|
| Мяу — герой, название меньше, круглая Play с треугольником | Огромный объёмный логотип вместо персонажа |
| Один Play: круг + слово «Играть» для взрослого | Три равных кружка без иерархии |
| Подсказка «Нажми, чтобы играть» у CTA | Тап по всему экрану без явной цели |
| Место под hero-арт **или** декоративный фон за заголовком | Emoji-кот в пузыре как «контент» |
| Звук / родители — мелкие, сбоку | Шестерёнка того же размера, что Play |

Референс владельца (кот-планета) = **настроение**, не пиксель-в-пиксель. Финальный арт — мегафайл `WELCOME-hero`.

## Меню плиток

- В сетке **9 карточек**, **2 колонки**. «В гостях у Мяу» — такая же карточка, одно имя.
- Назад на welcome — видимая тихая кнопка. Свайп от левого края остаётся вторым способом.
- Плитки **1:1**, крупные, отделены от фона (карточка/тень).
- Скролл **только** у поля плиток; страница зафиксирована; **полоса скролла скрыта**.
- Мяу-ведущий — заметная доля экрана (~⅓).
- На меню **нет chrome и нет футера**.
- Родители — шестерёнка **внизу блока Мяу** (тихо, не конкурирует с «В гости»).
- Выход на приветствие — **жест**: свайп вправо от левого края (кнопки «Назад» нет).

## Источники (коротко)

NN/g kids touch (~2cm targets), LukeW toddler splash (не мучить сплэшами), PBS KIDS / Sago — спокойный тон, TIDRC / docs/09.

## После правок UI

1. Прогнать self-check из reference.
2. Unit/e2e по skill `testing-and-verification`.
3. Поднять `npm run dev`, дать ссылку владельцу.
4. Зафиксировать решение в `docs/04-DECISION-REGISTER.md` при смене паттерна.

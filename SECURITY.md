# Политика безопасности

Простыми словами: этот проект — детское PWA-приложение **без сервера, без базы данных,
без аккаунтов, без API**. Поэтому классических «серверных» уязвимостей (SQL-инъекции,
утечки БД, взлом аутентификации) здесь физически не может быть — их не с чем ломать.
Актуальные риски — на стороне браузера/клиента и зависимостей npm.

## Как сообщить об уязвимости (без публикации email)

Используется встроенный в GitHub приватный канал — **Private vulnerability reporting**.
Он не требует email и не раскрывает детали уязвимости публично до исправления.

1. Откройте вкладку **Security** репозитория → **Advisories** → кнопка
   **Report a vulnerability**.
   Прямая ссылка: https://github.com/bogdanuz/meow-planet/security/advisories/new
2. Если кнопки/ссылка не работают — значит, функцию ещё нужно включить один раз:
   `Settings → Security → Advanced Security → Private vulnerability reporting → Enable`
   (это делает только владелец репозитория, вручную в браузере GitHub).
3. Опишите: что нашли, как воспроизвести, какое возможное влияние.
4. Ответ — обычно в течение 14 дней (проект поддерживается одним человеком без
   выделенной security-команды).

Источник механизма (официальная документация GitHub):
https://docs.github.com/en/code-security/security-advisories/working-with-repository-security-advisories/configuring-private-vulnerability-reporting-for-a-repository

## Что покрывает эта политика

- XSS/инъекции в клиентском коде (например, через имя ребёнка — оно обязано вставляться
  как текст, не HTML, см. `AGENTS.md`).
- Проблемы в обработке `localStorage` (единственное «хранилище» в проекте).
- Уязвимости в npm-зависимостях (см. также автоматические предупреждения Dependabot,
  `.github/dependabot.yml`).
- Некорректная работа Service Worker / PWA-кэша, которая может привести к утечке данных
  между устройствами/пользователями одного iPad.

## Что НЕ покрывает (не применимо к проекту)

- Аутентификация, сессии, API-эндпоинты, CORS, rate limiting — сервера нет.
- Утечки БД — базы данных нет.
- Обычные баги без последствий для безопасности — заводите как обычный Issue
  («🐛 Баг»), не как уязвимость.

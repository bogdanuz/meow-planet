# Как взаимодействовать с проектом

**Короткая версия: этот проект закрытый (проприетарный). Внешние Pull Request с кодом
не принимаются.** Весь код пишет владелец (с помощью AI-агента в Cursor) — см. `LICENSE`.

## Что можно

- Открыть **Issue** с идеей, вопросом или найденным багом — через шаблон в разделе
  «Issues» этого репозитория.
- Сообщить об уязвимости — см. `SECURITY.md` (приватный канал GitHub, без email).

## Что нельзя

- Присылать Pull Request с кодом «в помощь» — они будут закрыты без рассмотрения.
  Причина: право использовать/изменять код принадлежит только правообладателю
  (см. `LICENSE`), это не открытый для правок проект.
- Форкать репозиторий и публиковать свою/изменённую версию.

## Исключение: Dependabot

Автоматические Pull Request от бота **Dependabot** (обновления версий библиотек,
`.github/dependabot.yml`) — это не «чужой код», а служебные PR для владельца. Их можно
и нужно самостоятельно просматривать и подтверждать (мержить) через GitHub Desktop
или прямо на сайте GitHub.

## Как в проекте устроена работа с git (важно для агента Cursor)

Владелец делает коммиты и синхронизацию **только через приложение GitHub Desktop**,
не через консоль/терминал. Поэтому:

- **AI-агент Cursor никогда не выполняет `git commit` / `git push`** и любые команды,
  меняющие историю git, даже если это кажется удобным сократить путь. Агент готовит
  файлы — коммит и отправку на GitHub делает владелец сам.
- Агент может использовать только «безопасные» команды чтения git (`git status`,
  `git log`, `git diff`) — если это нужно для диагностики.

## Формат сообщений коммита (рекомендация, не обязаловка)

Удобно (но не критично) использовать Conventional Commits
(https://www.conventionalcommits.org/), например:

- `feat: добавить игру "Лопни шарик"`
- `fix: поправить soft-error в сортировке`
- `docs: обновить дорожную карту`
- `chore: обновить зависимости`

Это помогает потом собирать `CHANGELOG.md`, но если не хочется думать над форматом —
можно писать коммиты просто по-русски своими словами.
